# Phase 3.3 Tasks — Dependency Intelligence

Dependency-ordered, test-first, same discipline as 3.1/3.2.

1. **Ownership pre-flight** — read `CodebaseRecord`/`CodeFileRecord`/`CodebaseRepository`/`CodeSearchStore`/`CodebaseIndexer`/`SqliteCodebaseRepository`/`SqliteCodeSearchStore` and migrations 0003/0004 directly; resolve how `@brain/codebase` gets file source text without depending on `@brain/storage` (disk re-read via `rootPath`, mirroring `CodebaseIndexer` itself — `CodeFileRecord` carries no content and chunk-reconstruction isn't hash-safe). Document in `PHASE_3_SPEC.md` Part C.
2. **Contracts** — `packages/core/contracts/src/code-dependency.ts`: `CodeDependencyEdge` (schema-enforced `targetFileId` iff `resolution==='internal'`), `DependencySyncResult`. `CodeDependencyStore` interface added to `repositories.ts`. Tests in `code-dependency.test.ts`.
3. **Migration** — `packages/storage/migrations/0005_codebase_dependencies.sql`: `code_dependency_edges` (no FK on `source_file_id`/`target_file_id`), `code_dependency_state` (no FK on `file_id` — same orphan-detection-window reason as 0004's `code_embedding_state`). `0003`/`0004` untouched. Update the two hardcoded `appliedMigrations(...)` assertions plus table-existence checks in `db.test.ts`.
4. **Storage implementation** — `packages/storage/src/code-dependency-store.ts`: `SqliteCodeDependencyStore`. Unit tests in `code-dependency-store.test.ts`: write/read roundtrip, wholesale replace, **repository-scoped delete** (a real bug caught by the isolation test — the initial `DELETE ... WHERE source_file_id = ?` had no `repository_id` clause), targeted `updateEdgeResolution`, `removeFileState`, transactional atomicity.
5. **Fake + conformance** — `packages/core/test-fixtures/src/fake-code-dependency-store.ts` + `code-dependency-conformance.ts` (`runCodeDependencyStoreConformance`, mirroring 3.2's `code-store-conformance.ts`), wired into `fakes.test.ts` and against `SqliteCodeDependencyStore` — one contract, both implementations, closing an initial gap where the fake had no conformance coverage at all.
6. **Extraction (pure, TDD-first)** — `dependency-mask.ts` (`maskComments`, a small lexical state machine: blanks comments, passes every string literal through untouched so a `//`/`/*` inside a string is never mistaken for a real one) → `dependency-extract.ts` (five independent regex rules + dedup-by-specifier+kind) → `dependency-resolve.ts` (`resolveSpecifier`, deterministic candidate precedence). Each has its own test file, written and green before the next was started.
7. **Synchronizer + graph service** — `dependency-synchronizer.ts` (`DependencySynchronizer`, two-phase: content-hash-gated parse, inventory-gated re-resolve) and `dependency-graph.ts` (`DependencyGraphService`: `dependenciesOf`/`dependentsOf`/`impactOf`, reverse BFS, cycle-safe via pre-visiting the origin). `hash.ts` gained `deriveEdgeId`. Tests: `dependency-synchronizer.test.ts` (real tmp-dir fixture repos, real file edits/deletes), `dependency-graph.test.ts` (chain/cycle/diamond fixtures via the fakes). Export all five new modules from `index.ts`; add a `no SQLite import` structural guard alongside the existing `no networking import` one in `indexer.test.ts`.
8. **Real-repository bug found and fixed** — the self-repository integration run (step 10) surfaced that `resolveSpecifier` never resolved a single one of this repository's own imports: every relative import here uses an explicit `.js` extension (TS/ESM convention: source references the compiled output) while the indexed file is `.ts`. Fixed by stripping any recognized extension from the candidate base before re-appending each supported extension, so `./db.js` correctly tries `db.ts`, with the literal `./db.js` still checked first and winning if a real `.js` file exists. Two new tests added (`dependency-resolve.test.ts`) before the fix, confirming the bug, then the green fix. Full internal-edge count on this repository went from 0/247 relative imports resolved to 218/247 (29 genuinely unresolved) once fixed.
9. **Fixture evaluation** — `packages/evaluation/src/dependency-graph.data.ts` (9 hand-labeled ground-truth edges across a small synthetic repository covering comments, dynamic import, re-export, extensionless path, directory index, external package, missing target, and a 2-node cycle) + `dependency-graph-evaluation.test.ts` (precision/recall/resolution-accuracy against real `SqliteCodebaseRepository`/`SqliteCodeDependencyStore`, plus a qualitative `impactOf` cycle demo).
10. **Self-repository evaluation + performance baseline + impact demonstration** — `packages/evaluation/src/dependency-self-repository.test.ts`: indexes and resolves the real ai-brain repository; reports files eligible/parsed/unchanged, internal/external/unresolved edge counts, cold/warm sync duration; reports `dependenciesOf`/`dependentsOf` for 5 representative files chosen by reading actual source (barrel `index.ts` files, `db.ts`, `dependency-synchronizer.ts`); demonstrates `impactOf` on two real low-level files, including a genuine 3-level transitive chain. Added to `evaluation`'s `test:integration`.
11. **Full regression** — `npm run typecheck && npm run build && npm test && npm audit`; `packages/storage`/`packages/evaluation`/`packages/codebase` `test:integration` all green; total test count reported against the 533-test Phase-3.2 baseline.
12. **Readiness/report** — `docs/PHASE_3_READINESS.md` Phase 3.3 verdict; final report per the requested template.
